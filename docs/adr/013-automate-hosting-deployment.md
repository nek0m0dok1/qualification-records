# ADR-013：GitHub ActionsでFirebase Hostingへの公開を自動化する

- 日付：2026-10-09
- 状態：採用
- ファイル名：013-automate-hosting-deployment.md

## 背景

ソースコードはGitHubで管理し、公開先にはFirebase Hostingを採用している。

制作期間は約1か月であり、更新のたびに行う公開作業と、公開前の検証漏れを減らしたい。

## 決定

GitHub Actionsを使用し、mainブランチへの更新時に以下を順番に実行する。

1. 依存関係をインストールする。
2. TypeScriptとVueコンポーネントの型チェックを実行する。
3. Viteで公開用ビルドを生成する。
4. すべて成功した場合のみ、Firebase Hostingへ公開する。

途中で失敗した場合は公開せず、既存の公開内容を維持する。

## 比較した方針と理由

- 手動公開：設定は少ないが、毎回の操作と検証の実施を開発者に任せる。
- 自動公開：初期設定が必要だが、検証と公開を一定の手順で実行できる。

作業負担と確認漏れを減らすため、自動公開を採用する。

## 影響と制約

- 初期版ではプルリクエストごとの確認用URLを自動発行しない。
- 自動公開の対象はHostingのファイルと設定とする。
- Firestore Security Rulesなど、DB側の設定更新はこの公開処理に含めない。
- 公開に必要な認証情報はGitHub ActionsのSecretsなどで管理し、ソースコードに含めない。
- 型チェックとビルドの成功だけでは、操作やアクセス制御の正しさは保証しない。必要な動作検証は別途行う。

## 検証項目

- 型チェックまたはビルドが失敗した場合に、公開されない。
- 検証が成功したmainの更新が、公開サイトに反映される。
- 認証情報がログや公開ファイルに出力されない。
