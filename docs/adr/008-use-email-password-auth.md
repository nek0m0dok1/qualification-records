# ADR-008：メールアドレスとパスワードによる認証を採用する

- 日付：2026-10-09
- 状態：採用
- ファイル名：008-use-email-password-auth.md

## 背景

公開アプリとして、利用者ごとの資格・受験履歴を分離する必要がある。

コンテスト審査ではアカウントの使用が認められているが、事前にテスト用アカウントを用意し、審査員が操作できる状態にする必要がある。制作期間は約1か月である。

## 決定

初期版のログイン方法に、Firebase Authenticationのメールアドレス＋パスワード認証を採用する。

新規登録時に確認メールを送り、受信したリンクを一度開いてメールアドレスを確認する。確認済みアカウントは以後メールアドレスとパスワードでログインする。記録へのアクセスは確認済みの利用者に限定する。

審査用アカウントを事前に作成し、架空の資格・受験履歴を登録しておく。

## 比較した候補と理由

- メールアドレス＋パスワード：事前作成したアカウントを渡せる。ログイン時に審査員自身の外部アカウントやメール受信操作を必要としない。
- Googleログイン：審査員自身のGoogleアカウントが必要になる。
- メールリンク認証：ログイン時に受信メールを開く必要がある。

審査時の操作のしやすさを重視し、メールアドレス＋パスワードを採用する。

## 影響

- 一般利用者向けに新規登録・ログイン・ログアウト・パスワード再設定を用意する。
- パスワードの管理はFirebase Authenticationに任せ、Firestoreには保存しない。
- 審査用アカウントにも通常の利用者と同じアクセス制限を適用し、管理者権限を与えない。
- 審査用アカウントで一覧・詳細・検索・追加・編集を試せる状態にする。
- 審査用の認証情報は、提出先の指定方法で提供し、ソースコードには含めない。

## 運用上の初期設定

- 審査用アカウントは1つ用意し、必要なら審査時期ごとに利用者が手動で記録を初期化する。
- 初期版では、審査データの自動初期化・アカウント自動発行は実装しない。
