# ADR-010：JSONファイルによるバックアップ・復元を採用する

- 日付：2026-10-09
- 状態：採用
- ファイル名：010-json-backup-and-restore.md

## 背景

資格・受験履歴を利用者自身が保管し、必要なときに復元できるようにする。Firestoreの永続キャッシュは閲覧用であり、バックアップとしては扱わない。

コンテストへの出品を予定しており、制作期間は約1か月である。

## 決定

利用者本人の資格・受験履歴・タグ情報を、一つのJSONファイルへ書き出し、そのファイルから復元できる機能を採用する。

### 書き出し

- オンラインで本人の全記録を取得する。
- 全記録の取得に成功した場合のみ、バックアップファイルを生成する。
- 記録のIDと資格・受験履歴の対応関係を保持する。
- ファイル形式のバージョンと書き出し日時を含める。
- 資格・取得情報・受験履歴のID、固定タグ定義、取得・更新を根拠づける履歴IDと直前更新情報を含める。
- 認証情報やパスワードは含めない。

### 復元

- ファイル形式、バージョン、各項目と記録間の対応関係を検証する。
- 検証に失敗したファイルは復元しない。
- オンラインで、ログイン中の本人の保存領域へ復元する。所有者情報をバックアップに含めず、認証情報を出力しない。
- ファイル内の所有者情報を使って、他の利用者の領域へ書き込まない。
- 保存結果を確認してから復元完了を表示する。
- 形式・バージョン・日付・ID重複・資格と履歴の参照関係を全件検証し、失敗時は1件も書き込まない。
- 置換件数と既存データが消える警告を表示し、事前バックアップを任意で書き出せるようにする。
- 既存データと異なる一時データセットへ小さな単位で保存し、全記録を再取得して内容を比較した後、有効データセットIDをトランザクションで切り替える。
- 準備中に既存領域が変更された場合は切り替えず、既存データを維持する。切り替えの応答が失われた場合はサーバー状態を確認し、確認できるまで完了や再実行を案内しない。
- 失敗した一時データセットと切り替え済みの旧領域は削除する。中断した削除は次回オンライン時に再開する。永続的な履歴・クラウドバックアップとして残さない。

## 比較した形式と理由

- JSON：資格と受験履歴の関係やタグを、一つのファイルで表現しやすい。
- CSV：表計算ソフトで扱いやすいが、複数種類の記録とその関係を復元するための設計が増える。

アプリへの復元を主目的として、JSONを採用する。

## 影響と制約

- 書き出し・復元にはインターネット接続が必要になる。
- JSONファイルは利用者が保管する。初期版ではファイルの暗号化を行わない。
- Firebaseを利用したバックアップは、別のADRで扱う。
- データセットの切り替え用に追加した領域は、復元を安全に確定するための一時領域であり、追加バックアップではない。

## 今後の展望

重複対策は初期版の必須範囲に含めない。今後、以下を検討する。

- 同じバックアップを複数回復元した場合の重複防止
- 既存記録との照合・統合
- 重複した記録をスキップ、追加、更新する方法の選択

## 検証項目

- 書き出したファイルから、資格・受験履歴・タグの対応関係を復元できる。
- 不正な形式や未対応バージョンを拒否できる。
- 他の利用者の保存領域へ書き込めない。
- 取得・保存に失敗した場合、完了と表示しない。
