# ADR-015：主要画面にVue Routerのファイルベースルーティングを採用する

- 日付：2026-10-09
- 状態：採用
- ファイル名：015-use-vue-router.md

## 背景

現状の主要画面は「あなたの資格」と「受験履歴」の2ページであり、今後増える可能性がある。入力はウィザード形式のポップアップを想定している。

制作期間は約1か月であり、ページ追加時に必要な設定と保守の負担を抑えたい。

## 決定

主要画面の切り替えにVue Routerを使用し、ページファイルからルートを自動生成する。

- Vue RouterのVite向けファイルベースルーティングプラグインを使用する。
- ページはsrc/pagesに配置し、ファイル名とフォルダー構成からURLを生成する。
- 例として、src/pages/records.vueは/recordsに対応する。
- 入力ウィザードや共通部品はページ用フォルダーの外に配置し、ルート生成の対象にしない。
- 将来の主要画面は、ページファイルを追加して対応する。

## 比較した方針と理由

- 手動設定：URLとコンポーネントの対応を明示できるが、ページ追加・変更時にルート設定も更新する必要がある。
- 自動生成：所定の命名規則に従うことで、ページファイルから対応するルートと型を生成できる。

期限内の開発と設定の重複削減を重視し、自動生成を採用する。

## 影響と制約

- 初期設定で、ルート生成プラグインとTypeScriptの型生成を組み込む。
- 型チェックの前に、ルートの型生成が行われるよう自動公開の手順を調整する。
- ページファイルの移動・改名はURLの変更につながるため、公開後は影響を確認する。
- ポップアップの開閉とウィザードの進行は、ページ内の状態として管理する。
- 直接アクセス・再読み込み・オフライン表示ができるよう、HostingとService Workerの設定を合わせる。
- データのアクセス制御は、引き続きFirestore Security Rulesで行う。

初期ルートは `/qualifications` とし、ほかに `/exam-attempts`、`/settings`、`/login`、`/register`、`/reset-password` を使用する。履歴方式は通常のパス。資格詳細はポップアップで表示する。検索状態は画面ごとに保持し、再読み込み時は初期化する。ウィザードの途中で画面を移動するときは、破棄警告を閉じた後に進捗をリセットする。
