# 資格管理アプリ：データの扱い

本書は、登録・入力検証・更新・表示・保存・復元のルールを定義する。項目・型・参照関係は `data-model.md` を参照する。

未決定事項は推測で実装せず、プロダクト範囲から除外するか将来検討として明記する。

## 目的

あなたの資格と取得年月を簡単に確認できるようにする。受験履歴は、合否にかかわらず記録できるようにする。

受験履歴がなくてもあなたの資格を登録できること。

## 登録フローと入力検証

新たに登録・変更する年月・受験日は1900年から2100年まで（両端を含む）とする。保存済みデータの検証・表示・書き出し・JSON復元は従来どおり西暦1年から9999年まで扱い、既存の日付を範囲外という理由で変更・削除しない。既存の日付を編集せずに資格情報などを更新する場合も、その日付を保持できる。

新資格の登録は対象を選ぶ4段階のウィザードで行う。資格詳細から既存資格へ更新・履歴を追加する場合は、その資格IDを引き継ぐ独立した3段階のモーダルを使う。どちらも結果に応じて入力手順・必須条件・保存内容を切り替える。

全分岐で資格名は必須、固定タグは任意とする。既存資格の場合は保存済みの資格情報を引き継ぎ、再入力を求めない。

### 対象資格の選択

| 選択 | 処理 |
|---|---|
| 新資格の登録 | 資格情報を入力し、保存時に新しい資格IDを作成する |
| 既存資格の更新 | 登録済みの資格を選択し、その資格IDと資格情報を引き継ぐ |

- 新資格では、既存資格と名前・級などが重複していても登録を許可する。
- 初期版では資格名による重複検出・自動統合を行わない。
- 既存資格では資格情報を別IDで重複作成しない。
- 既存資格への受験履歴の追加も、このウィザードで行う。
- 重複を許可する場合も、必須項目・日付形式は検証する。

### 合格の場合

1. 結果として「合格」を選択する。
2. 資格情報を入力、または選択済みの資格情報を確認する。必須項目を検証してから次へ進む。
3. 資格情報の入力・確認完了時に「受験履歴も登録しますか？」を表示し、「履歴も登録する」「あなたの資格のみ登録する」を明示的に選択させる。
4. 取得情報の有無に応じて年月を入力する。
   - 取得情報なし：取得年月を必須とする。
   - 取得情報あり：更新年月を必須とする。既存の取得年月は表示・保持し、再入力を求めない。
5. 履歴登録を選択した場合は、受験年月を必須、日を任意として受験情報を入力・検証する。
6. 保存対象を確認し、必要な情報がすべて有効な場合のみ保存する。

取得年月・更新年月の具体的な画面配置は調整できるが、履歴登録の分岐は資格情報の入力・確認完了時に提示する。

履歴登録を選択した後は、受験年月の未入力・不正を許可しない。次のステップへの移動と最終保存の両方で検証する。

取得情報がない既存資格も、取得年月を入力して取得情報を作成する。更新年月だけではあなたの資格を登録しない。

### 不合格・結果待ちの場合

1. 結果として「不合格」または「結果待ち」を選択する。
2. 資格情報を入力・確認し、必須項目を検証する。
3. 受験年月を必須、日を任意として受験情報を入力・検証する。
4. 内容を確認し、有効な場合のみ受験履歴を保存する。

履歴登録は必須なので、登録するかどうかの分岐を表示しない。

取得年月・更新年月の入力は求めず、取得情報を作成・更新しない。保存済みの取得年月・更新年月も変更しない。

### 分岐ごとの保存条件

| 条件 | 履歴登録 | 必須の年月 | 保存内容 |
|---|---|---|---|
| 取得情報なし・合格 | 登録しない | 取得年月 | 取得情報を作成 |
| 取得情報なし・合格 | 登録する | 取得年月・受験年月 | 取得情報と合格履歴を作成 |
| 取得情報あり・合格 | 登録しない | 更新年月 | 取得情報の更新年月を更新 |
| 取得情報あり・合格 | 登録する | 更新年月・受験年月 | 更新年月を更新し、合格履歴を作成 |
| 不合格 | 必須 | 受験年月 | 受験履歴を作成 |
| 結果待ち | 必須 | 受験年月 | 受験履歴を作成 |

受験日は全分岐で日だけ任意とする。履歴登録を選択しなかった場合、受験情報は保存しない。

新資格では資格情報も作成し、作成した記録から同じ資格IDを参照する。既存資格では選択済みの資格IDを使用する。

### 共通情報の引き継ぎ

- 資格名・級または区分・固定タグ・資格IDを、共通の入力状態として保持する。
- 受験情報の入力時に資格情報を再入力させない。
- 合格の結果も引き継ぎ、再選択を求めない。
- 受験情報のステップに対象資格を表示する。
- 共通情報を修正する場合は、以前の入力ステップへ戻れるようにする。
- 取得年月・更新年月・受験日を自動的に同じ値にしない。

### 入力途中の状態

新資格・既存資格の選択と履歴登録の選択は、ウィザードの制御状態として保持する。これらのフラグを永続データに追加する必要はない。

- 新資格・既存資格が未選択なら次へ進めない。既存資格では対象資格の選択も必須とする。
- 合格時に履歴登録の有無が未選択なら、確認・保存へ進めない。
- 履歴登録を取り消した場合、入力途中の受験情報を保存対象から外す。
- 再び履歴登録を選択した場合、受験情報を再検証する。
- 結果を変更した場合、表示・必須条件・保存対象を切り替える。
- 不合格・結果待ちに変更した場合、入力途中の取得年月・更新年月を保存対象から外す。保存済みの取得情報は変更しない。
- 対象資格や新規・既存の選択を変更した場合、以前の資格ID・取得情報・入力値を誤って保存しないよう再評価する。
- ステップ移動時に加え、保存直前にも全保存対象を検証する。
- 入力中・ステップ移動だけでは正式な記録を保存しない。
- キャンセルした場合、正式な記録を作成・更新しない。

## 取得情報と更新年月の扱い

- 初期版では同じ資格IDの取得情報を1件に制限する。
- 既存の取得情報がある場合は、新しい取得情報を追加せず、更新年月を更新する。
- 取得・更新の対象となる合格履歴がある場合はそのIDを取得情報に保存する。履歴を登録しない合格と更新も許可する。
- 取得年月は別項目として保持し、資格の更新では変更しない。
- 更新年月は資格そのものを更新した年月であり、記録の編集日時ではない。
- 最新更新と直前更新を1件ずつ保持する。更新時には最新更新を直前情報へ移し、それより古い更新情報は保持しない。
- 根拠履歴なしの更新でも同じように直前更新を保持する。最新更新は直前更新へ1回だけ戻せる。
- 取得の根拠履歴が訂正・削除された場合は、確認のうえ取得情報と更新情報を削除する。資格情報と他の受験履歴は残す。
- 最新更新の根拠履歴が訂正・削除された場合は、直前更新があればそこへ戻し、なければ更新情報を削除する。取得年月は維持する。
- 直前更新の根拠履歴が訂正・削除された場合は、確認のうえ巻き戻し用の直前情報を削除する。
- 受験履歴と取得情報は、対象選択、結果訂正、削除時に整合性を保つ。同意しない場合は履歴変更も含めて全操作を取り消す。
- 資格全体の削除は資格情報・取得情報・その資格の全受験履歴を対象とし、確認後に一括で実行する。
- 保有情報だけの削除は初期版では提供しない。開発処理に「保有情報のみの削除は未実装です」と表示する仮置きエラーを残し、将来の要否を再検討する。
- 更新年月の目的は将来の有効期限の可視化であり、記念・コレクションのための履歴保存ではない。
- 初期版では有効期限を自動算出しない。

## 日付・参照関係の検証

- 必須項目の欠落、空文字・空白のみの資格名、不正な結果の値を拒否する。
- 年月・日付の形式と実際の暦を検証し、存在しない月・日を拒否する。
- 日不明の受験日を補完せず、入力された精度で保持する。
- 存在しない資格IDや、他の利用者の資格IDを参照する記録を保存・復元しない。

取得年月・更新年月は `YYYY-MM` の文字列とし、存在する年月を検証する。更新年月が取得年月より前なら拒否する。受験年月は `YYYY-MM` または `YYYY-MM-DD` の文字列で検証し、取得・更新年月との前後関係は制限しない。時刻・タイムゾーン変換を使わず、ゼロ埋めされた文字列と年月・日部分を比較する。

## 一覧・検索・並べ替え

- あなたの資格は資格情報と取得情報を組み合わせて表示する。
- あなたの資格は取得年月順とする。更新年月によって並べ替え基準を変更しない。
- 受験履歴は受験年月順とする。
- 同じ月では日が分かる履歴を日順に並べ、日不明の履歴は昇順・降順とも月の末尾に置く。
- 両一覧とも初期表示は降順で、昇順に切り替えられるようにする。
- 同じ日付の記録はIDなどで順序を安定させる。
- 資格名の部分一致検索、あなたの資格の固定タグによる絞り込み、受験履歴の結果による絞り込みを提供する。
- 資格名は入力文字列を変換せず、部分一致で検索する。大文字・小文字、全角・半角、ひらがな・カタカナの同一視はしない。
- 固定タグを複数選択した場合、資格が選択済みのすべてのタグを持つものだけを表示する（AND）。タグでの並べ替えはしない。
- 名前検索と選択済み絞り込みはANDで組み合わせる。タグ未選択なら全件を候補とする。
- 検索・絞り込み・並べ替えは、取得済みの本人の記録を対象に端末内で行う。

一覧ごとの検索・絞り込み・並び順は独立して保持し、画面を切り替えて戻っても条件を保つ。再読み込み時は初期状態に戻す。

## 保存とアクセス制御

- 正式な保存先はCloud Firestoreとする。
- Firebase Authenticationで利用者を識別する。
- 新規登録時に確認メールを一度送り、受信メールのリンクを開いた確認済みアカウントのみ記録機能を利用できる。以後はメールアドレス・パスワードでログインする。
- Firestore Security Rulesで確認済み本人の記録のみ読み書きできるようにする。画面の制限だけで保護しない。
- オフライン閲覧用の保存はFirestoreの永続キャッシュを使用する。
- 端末保存を利用者が選択できるようにする。オフライン時は閲覧・検索だけとし、記録の変更を無効にする。
- ログイン・アプリ復帰・再接続・保存後と手動操作で再取得する。変更はオンラインのトランザクションのみで保存し、後送りしない。
- キャッシュを正式なバックアップとして扱わない。
- ログアウト時はFirestoreを終了し、永続キャッシュを削除する。失敗時に完了と表示しない。

保存パスは `data-model.md` を参照する。

## JSONバックアップ・復元

### 書き出し

- オンラインで本人の全記録を取得できた場合のみ書き出す。
- 資格情報・取得情報・受験履歴と、タグ情報を復元できる内容を含める。
- 記録ID・参照関係・日付の精度を保持する。
- 固定タグ定義、任意メモ、取得・更新の根拠履歴、直前更新を保持する。
- 取得年月と最新の更新年月を別項目として保持する。
- 未更新の場合は更新年月なしの状態を保持する。
- ファイル形式のバージョンと書き出し日時を含める。
- 認証情報やパスワードは含めない。
- Firebaseの保存領域・データセットIDなどの所有者情報は含めない。

### 復元

- 形式・バージョン・日付・ID重複・固定タグ・参照関係をすべて検証してから復元する。
- 検証に失敗したファイルは復元しない。
- オンラインで、ログイン中の本人の保存領域へ復元する。
- ファイル内の所有者情報で復元先を変更しない。
- 件数と全置換の警告を表示する。事前バックアップの書き出しは任意とする。
- 既存領域と別の一時データセットへ小分けで保存し、サーバーから読み戻して全件を検証する。既存領域が準備中に変更された場合は切り替えず、再確認を求める。
- 準備完了後に有効データセットIDをトランザクションで切り替える。切り替え前に失敗した場合は既存記録を維持する。
- 切り替え応答が不明ならサーバー状態を確認し、確認できるまで完了・再実行を案内しない。
- 一時領域と旧領域は削除し、中断した削除は次回オンライン時に再開する。一時領域を恒久的なバックアップにしない。
- 保存結果を確認してから復元完了を表示する。
- 取得・保存に失敗した場合、完了と表示しない。

既存記録を無確認で上書きしない。Firebaseの正式データに追加バックアップは設けず、復元用一時データセットは確定切り替え後に削除する。

## 今後の展望

### 取得情報の複数登録

更新とは別の再取得などを、以前の取得年月を上書きせずに残すために検討する。複数回取得した経緯を記録できる意義がある。

取得情報の複数登録と、最新の更新年月の保持は目的が異なる。更新年月の履歴保存は初期版の対象に含めない。

### 新資格登録時の重複チェック

資格名・級による重複検出、表記揺れへの対応、別IDで登録された同一資格の統合を検討する。

### 有効期限の管理

取得年月・最新の更新年月を有効期限の可視化に活用する。資格ごとの有効期間・期限の規則と、年月だけでは期限を確定できない場合の扱いを別途定義する。

### 入力UXの改善

既存資格の候補表示や、資格詳細から資格IDを引き継いでウィザードを開く方法など、選択・再入力の手間を減らす改善を検討する。

## 将来の再検討事項

- 保有情報だけを削除する機能の要否。初期版では利用者向け操作を設けず、開発用の未実装メッセージを残す。
- 自由タグ、取得情報の複数登録、有効期限の管理。
- JSON形式に新しいバージョンを追加するときの旧形式変換。

初期版のモデルは `data-model.md` に記載した内容で確定する。

## 検証する挙動

### 登録・入力検証

- 新資格・既存資格を選択でき、既存資格では対象資格の選択が必須となる。
- 既存資格のIDと共通情報が引き継がれ、再入力を求められない。
- 新資格の重複は許可するが、必須項目や日付の不正は拒否する。
- 合格時、資格情報の入力・確認完了時に履歴登録の分岐が表示される。
- 履歴登録が未選択なら確認・保存へ進めない。
- 履歴なしでもあなたの資格を登録・更新できる。
- 履歴登録を選んだ場合、受験年月の未入力・不正をステップ移動時と保存時に拒否する。
- 受験日は年月だけでも登録でき、日を要求されない。
- 履歴登録を取り消すと、入力途中の受験情報は保存されない。
- 取得情報なしの合格登録では取得年月が必須となる。
- 取得情報ありの合格登録では更新年月が必須となり、取得情報を追加作成しない。
- 不合格・結果待ちでは受験年月が必須となり、取得情報を作成・更新しない。
- 戻る操作・分岐変更・対象資格変更後も、正しい条件と資格IDで検証・保存される。
- キャンセルで正式な記録が作成・更新されない。

### データ・表示・復元

- 同じ資格に複数の受験履歴を関連付けられる。
- 共通の資格情報の修正が関連する一覧へ反映される。
- 資格更新後も取得年月を維持し、更新年月だけを置き換える。
- 未更新の資格は更新年月なしで保存できる。
- 不正な日付を拒否し、日不明の記録を補完しない。
- 昇順・降順とも、日不明の履歴が該当月の末尾になる。
- 更新年月を保存しても、あなたの資格は取得年月順で並ぶ。
- 他の利用者の記録へアクセスできない。
- JSONでID・参照関係・日付の精度・取得年月・最新の更新年月を保持して復元できる。
- 不正なファイルを拒否し、取得・保存の失敗を完了として扱わない。
