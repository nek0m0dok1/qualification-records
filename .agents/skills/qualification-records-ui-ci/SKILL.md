# フォーム表示変更時のCI失敗を防ぐ

## 変更前の確認
- tests/e2e/qualification-flows.spec.ts の getByLabel・getByRole と、
  exact: true を使う検索条件を確認する。
- 装飾の追加がラベル文字列やアクセシブルな名前を変えないか確認する。

## 必須マーカー
- 赤いアスタリスクは、空の aria-hidden="true" の
  required-marker 要素とCSSの疑似要素で1つだけ表示する。
- aria-hiddenだけでは、PlaywrightのgetByLabelが参照する
  ラベル文字列から装飾文字を除けるとは限らない。
- テストを通すためだけに完全一致を外さず、表示とラベル名の両方を確認する。
- 意図してラベル名を変更する場合は、関連テストも変更する。

## 検証
- npm run checkは型チェック・単体テスト・ビルドのみで、
  FirestoreルールテストとE2Eテストは含まない。
- フォームのラベル変更ではnpm run test:e2eを実行し、
  実際の入力操作まで確認する。
- ローカル実行がポート競合や環境制約でできない場合は、
  未検証と報告し、プッシュが許可されていればActionsで確認する。
- Actions確認時は最新コミットのSHAと実行結果を照合する。
  E2Eを含む全チェック完了前に成功と報告しない。

## 失敗・表示不一致への対応
- 失敗したステップとログを読み、要素が見つからない場合は
  実際のラベル文字列とテストの検索条件を比較する。
- 原因や条件が変わらないまま再実行を繰り返さない。
- アスタリスクが重複する場合は、DOMの文字と疑似要素を確認する。
  入力中の内容を確認してから再読み込みし、古い表示かコードの問題かを区別する。
- 検証不能なら、制約と残る確認事項を報告する。
