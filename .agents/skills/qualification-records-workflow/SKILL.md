# このプロジェクトの実装とレビュー

## 担当
- 実装とGit操作は「実装/Git担当」、すべての変更の独立レビューは「コードレビュー」が担当する。UI・UX担当など他のチャットは調査・提案を行い、直接アプリを変更せず実装担当へ渡す。コード、テスト、設定、文書を対象から除外しない。
- 確認済みの実装担当IDは `01a12061-864d-7931-aeb5-4eb866f73ca6`、レビュー担当IDは `01a12173-e65d-7ec0-9bb8-4ed487e0dfb8`。list_threadsで同一プロジェクト所属と現在の題名を確認してから使う。不在・変更・曖昧な場合は確認し、別担当や新規チャットで無断代用しない。
- この担当分担と相互の実装・レビュー依頼は、ユーザーの継続的な指示である。同じ範囲の送信許可を毎回取り直さない。環境の承認、個別の実行前確認、push・公開等の許可は別に守る。他プロジェクトへ許可を広げない。
- 今回のスキル整備のようにユーザーが特定チャットへ明示した設定管理は、その依頼範囲で行える。アプリ実装の担当分担を変更する例外とは扱わない。

## 実装から合格まで
1. 自分が担当でなければ、要求・変更範囲・制約を実装担当へ正式な送信ツールで引き継ぐ。受領・開始を確認し、送信失敗を完了扱いにしない。実装担当は実際の作業ディレクトリ・Git状態・既存変更を確認して作業する。worktreeが必要ならprepare-parallel-worktreesを使うが、別エージェントへ実装を分散しない。
2. 実装担当は変更と必要な検証を終えたら、対象SHAまたは未コミット差分、変更ファイル、目的、検証結果、未確認事項を「コードレビュー」へ実際に送信する。送信成功と受領・開始を確認する。report-fix-resultsで報告をまとめ、未レビューなら「実装完了・レビュー待ち」とする。
3. レビュー担当はindependent-review-handoffに従い、対象変更全体と統合後の影響を確認する。コードは変更しない。問題は優先度・場所・発生条件・原因・修正方向・回帰検証を添えて、必ず同じ「実装/Git担当」へ戻す。別モデル・別修正チャットを新設しない。
   Vue SFCのテンプレート変更や整形を含む場合、レビュー担当は最終差分を対象にしたVueコンパイルまたはビルド結果を確認する。ESLint・Prettierだけ、またはソースの読み取りだけで構文妥当と判断しない。検証が未実行・失敗・対象を含むか不明なら、未確認事項として報告する。
4. 修正担当が結果を返し、レビュー担当が独立再レビューする。追加変更も対象へ含め、合格まで繰り返す。実行不能・承認待ちは理由と残る対応を報告する。
5. 合格後、レビュー担当はindependent-review-handoffの記録手順で、保管庫の `90_codex/qualification-records` に通し番号付きMarkdownを保存・読み戻しし、リンクを報告する。変更・実際の失敗と対処・最終結果を簡潔に記す。未保存なら全工程完了としない。Git操作は実装担当へ戻し、合格後でも追加変更は再レビューする。

このスキルは担当分担を定める手順であり、自動監視や送信の仕組みを常駐させるものではない。
