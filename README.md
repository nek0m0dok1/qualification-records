# Tsumica（ツミカ）

## アプリ概要

Tsumica（ツミカ）は、自分の資格と取得・更新年月、受験結果をまとめて記録し、必要なときに探せるWebアプリです。資格名・級や区分・ジャンル・メモと、合格・不合格・結果待ちの受験履歴を管理できます。受験履歴が残っていない資格も、取得年月だけで登録できます。

記録は利用者ごとにCloud Firestoreへ保存します。JSONファイルへのバックアップと復元、任意の端末保存による取得済み記録のオフライン閲覧に対応しています。画面はVue 3・TypeScriptで実装し、認証にはFirebase Authenticationを使用しています。

## 目的

履歴書を書くときや過去の受験を振り返るときに、「どの資格を、いつ取得・更新したか」「いつ受験して、どんな結果だったか」を確認しやすくすることを目指しています。資格情報と受験履歴を関連付け、資格名の検索や絞り込みから必要な記録へたどれるようにします。

## 利用方法

### 1. アカウントを登録してログインする

1. ログイン画面の「アカウント登録」から、メールアドレスとパスワードを入力します。
2. 届いた確認メールのリンクを開き、アプリに戻って「メール確認の完了を確認」を押します。メール確認が完了するまで記録機能は利用できません。
3. 次回からは同じメールアドレスとパスワードでログインします。パスワードを忘れた場合は「パスワードを忘れた場合」から再設定メールを送れます。

「ログイン状態を記憶する」を選ぶと、次回起動時もログイン状態を保持します。未選択ではタブを閉じるまでの保持です。パスワード自体をアプリに保存する設定ではありません。パスワードの保存はブラウザーの機能で設定できます。共用端末ではログイン状態の記憶を選ばないでください。

記録の端末保存は別の設定です。詳しくは[オフライン利用と復元時の上書き](#オフライン利用と復元時の上書き)をご覧ください。

### 2. 資格・受験の記録を追加する

「＋ 記録を追加」から、次の4段階で登録します。

1. **対象**：「新資格の登録」または「既存資格の更新・受験履歴の追加」を選びます。既存資格の場合は対象資格も選択します。
2. **資格・結果**：新資格では資格名を入力し、必要に応じて級・区分、ジャンル、メモを追加します。既存資格では保存済み情報を引き継ぎます。どちらも受験結果を「合格」「不合格」「結果待ち」から明示的に選びます。
3. **年月**：結果に応じた年月を入力します。下表をご確認ください。
4. **確認**：内容を確認して「記録を保存」を押します。確認画面まで進んでも、保存するまでは正式な記録は変わりません。

| 受験結果・資格の状態     | 入力する内容                           | 保存される内容                                                                           |
| ------------------------ | -------------------------------------- | ---------------------------------------------------------------------------------------- |
| 合格・取得年月が未登録   | 取得年月と、受験履歴を登録するかどうか | 取得情報。履歴も登録する場合は受験年月（日は任意）と合格履歴                             |
| 合格・取得年月が登録済み | 更新年月と、受験履歴を登録するかどうか | 元の取得年月を保持して更新情報を保存。履歴も登録する場合は受験年月（日は任意）と合格履歴 |
| 不合格・結果待ち         | 受験年月（日は任意）                   | 受験履歴。取得・更新情報は作成・変更しません                                             |

資格詳細の「更新・記録を追加」から始める場合は、対象資格を引き継ぐため「資格・結果 → 年月 → 確認」の3段階です。同じ資格への追加は既存資格を選んでください。同じ名前や級の新資格も登録でき、自動的な重複検出・統合は行いません。

取得・更新年月は `YYYY-MM`、受験年月は `YYYY-MM` または `YYYY-MM-DD` で入力できます。日は不明のまま登録でき、1日などで補完しません。新たに入力・変更する年は**1900年から2100年まで**です。更新年月は取得年月以降にしてください。保存済みの範囲外の日付は、それだけを理由に削除・変更せず、表示・書き出し・復元や日付を変えない編集で保持します。

更新年月は資格そのものを更新した年月です。取得年月とは別に保持し、最新更新と取り消し用の直前更新を1件ずつ保存します。それより古い更新情報をすべて蓄積する機能や、有効期限の自動計算はありません。

### 3. 一覧から探し、詳細を確認・訂正する

- **資格一覧**：取得情報のある資格を表示します。資格名の部分一致検索、ジャンルによる絞り込み、取得年月の新しい順・古い順で探せます。
- **受験履歴**：合否を問わず登録した履歴を表示します。資格名の部分一致検索、受験結果による絞り込み、受験年月の新しい順・古い順で探せます。
- **詳細**：一覧の資格や履歴を開くと、取得年月・最新更新年月・メモ・関連する受験履歴を確認できます。「情報を訂正」で資格情報を変更し、受験履歴側の詳細から履歴を訂正・削除できます。

名前検索では大文字・小文字、全角・半角、ひらがな・カタカナを区別します。資格のジャンルを複数選ぶと、すべての選択ジャンルを持つ資格に絞り込みます。検索・絞り込み・並び順は一覧ごとに保持しますが、再読み込みすると初期状態に戻ります。

取得や更新の根拠となる合格履歴を訂正・削除すると、取得・更新情報にも影響する場合があります。確認画面の影響を読んでから実行してください。「資格全体を削除」は、その資格の取得・更新情報と全受験履歴もまとめて削除します。最新更新の取り消しは1回分で、取得年月と合格履歴は残します。

### 4. 設定・バックアップを開く

「設定・バックアップ」では端末保存の切り替え、JSONバックアップの書き出しと復元を行えます。操作前に、次の節で保存先と上書き範囲をご確認ください。

## オフライン利用と復元時の上書き

### ログイン保持と端末保存の違い

| 設定・保存先                 | 役割                                                                         |
| ---------------------------- | ---------------------------------------------------------------------------- |
| 「ログイン状態を記憶する」   | 次回起動時のログイン状態を保持します。資格記録の端末保存とは別です           |
| 「この端末に記録を保存する」 | Firestoreの永続キャッシュに取得済みの記録を保存し、オフライン閲覧に使います  |
| Cloud Firestore              | ログイン中の本人の記録を保存する正式な保存先です                             |
| 書き出したJSONファイル       | 利用者が端末などに保管するバックアップです。クラウドの記録とは別に管理します |

端末保存は「設定・バックアップ」の「ネットなしで見る」から有効にします。再読み込み後、オンラインで記録を取得しておいてください。オフラインで利用できるのは**取得済み記録の閲覧・検索のみ**です。記録の追加・訂正・削除、バックアップの書き出し・復元には接続が必要で、オフラインの変更を後から送信する機能はありません。

画面表示用のファイルにも初回のオンライン取得が必要です。保存状況やブラウザーの制約により、オフラインで表示できない場合があります。ホーム画面への追加・インストール対応は初期版の必須範囲に含めていません。

キャッシュはバックアップではなく、ブラウザーのデータ消去などで失われます。共用端末では端末保存を有効にしないでください。ログアウト時には端末の記録を削除します。削除未完了の案内が出た場合は、他のタブを閉じて削除を再試行してください。端末保存を無効にするときも、ログアウトして保存済みデータを削除します。

### バックアップを書き出す

オンラインで「バックアップを書き出す」を押すと、本人の全記録を再取得し、JSONファイルのダウンロードを開始します。保存先を確認し、大切に保管してください。資格情報・取得更新情報・受験履歴・タグ・メモを含みますが、認証情報やパスワードは含みません。共用端末ではダウンロードしたファイルの扱いにもご注意ください。

製品名が変わっても、既存バックアップとの互換性のため内部形式名は `qualification-records`、バージョンは `1` のままです。データの詳細は[データモデル](docs/database/data-model.md)と[データの扱い](docs/database/data-handling.md)を参照できます。

### JSONから復元する前に

**復元は追加・統合ではなく、ログイン中の本人のクラウド上の全記録を、ファイルの内容へ置き換える操作です。** ファイルにない現在の記録は残りません。復元前に現在の記録を書き出し、別のバックアップとして保管することをおすすめします。事前書き出しは自動ではありません。

1. オンラインで「バックアップファイル」からJSONを選びます。ファイルは10MB以内です。
2. 形式・バージョン・日付・ID・タグ・参照関係などの検証を通過すると、件数と書き出し日時が表示されます。不正なファイルは復元できません。
3. 「内容を確認して全置換」を押し、既存記録が削除される警告を確認して実行します。

復元内容は別のデータセットへ準備し、サーバーから読み戻して検証した後に有効領域を切り替えます。切り替え前の失敗や、準備中に既存記録の変更を検出した場合は、既存記録を維持します。切り替え結果が未確認になった場合は再実行せず、「サーバー状態を確認」で結果を確かめてください。端末の復元状態を読み取れない場合も変更・復元を停止するため、画面の案内に従って再確認してください。

切り替えに使う一時領域・旧領域は恒久バックアップではなく、削除対象です。このアプリはJSON書き出しとは別のFirebase追加バックアップを提供しません。

## cloneして利用する際の手順

### 必要な環境と取得

- Git、Node.js 24とnpm
- クラウドへ接続する場合：自分で管理するFirebaseプロジェクト（Email/Password Authentication、Cloud Firestore。公開する場合はHostingも使用）
- EmulatorやSecurity Rulesのテストを使う場合：Java 21

```sh
git clone https://github.com/nek0m0dok1/tsumica.git
cd tsumica
npm ci
```

リポジトリ名は `tsumica` です。npmパッケージ名とバックアップ形式名は `qualification-records`、ローカルEmulatorのプロジェクトIDは `demo-qualification-records` を引き続き使用します。

続いて `.env.example` を `.env` にコピーします。OSに合うどちらかを実行してください。

PowerShell：

```powershell
Copy-Item .env.example .env
```

macOS・Linuxなどのシェル：

```sh
cp .env.example .env
```

以下の「Firebaseのクラウドに接続する」または「Emulatorだけで試す」のどちらかを選びます。クラウドを使う場合の設定値は、ご自身のFirebase管理画面から取得してください。秘密鍵・サービスアカウント情報・パスワードを `.env` やリポジトリへ保存・公開しないでください。

| 環境変数                    | 内容                                                          |
| --------------------------- | ------------------------------------------------------------- |
| `VITE_FIREBASE_API_KEY`     | Firebase Webアプリの `apiKey`                                 |
| `VITE_FIREBASE_AUTH_DOMAIN` | Firebase Webアプリの `authDomain`                             |
| `VITE_FIREBASE_PROJECT_ID`  | Firebase Webアプリの `projectId`                              |
| `VITE_FIREBASE_APP_ID`      | Firebase Webアプリの `appId`                                  |
| `VITE_USE_EMULATORS`        | 通常は `false`。開発時にローカルEmulatorを使う場合だけ `true` |

Firebase Webアプリの設定値はブラウザーで利用されます。APIキーを隠すことだけで記録を保護せず、確認済み本人のみ読み書きできるSecurity Rulesを適用してください。

### Firebaseのクラウドに接続する

1. [Firebase管理画面](https://console.firebase.google.com/)で自分のプロジェクトを作成し、プロジェクトIDを控えます。既存の構成はSparkプラン・Google Analytics無効を前提にしています。
2. Webアプリを登録し、表示されるFirebase設定の4項目を `.env` に入力します。`VITE_USE_EMULATORS=false` にします。
3. Authenticationのログイン方法で「メール / パスワード」を有効にします。メールリンク認証は使用しません。メール確認テンプレートを確認し、承認済みドメインにはローカル接続先の `localhost` と `127.0.0.1` を追加します（プロトコル・ポートは含めません）。
4. Cloud FirestoreをStandard版、データベースID `(default)`、東京 `asia-northeast1`、本番モードで作成します。同じデータベースの地域は作成後に変更できません。
5. Java 21を用意し、`npm run test:rules` でこのリポジトリのSecurity Rulesを検証します。テストは `demo-qualification-records` のローカルEmulatorを使います。
6. 下記のコマンドで自分のGoogleアカウントにログインし、対象プロジェクトを確認してからルールとインデックスを適用します。**既存の設定を変更する操作**なので、`YOUR_PROJECT_ID` を自分の対象IDに置き換え、他のプロジェクトに適用しないよう確認してください。

   ```sh
   npx -y firebase-tools@latest login
   npx -y firebase-tools@latest projects:list
   npx -y firebase-tools@latest deploy --only firestore --project YOUR_PROJECT_ID
   ```

   適用元は [firestore.rules](firestore.rules) と [firestore.indexes.json](firestore.indexes.json) です。Hostingの公開は含みません。

7. 開発サーバーを起動します。`.env` を変更した場合は再起動が必要です。

   ```sh
   npm run dev
   ```

8. `http://127.0.0.1:5173` を開き、[利用方法](#利用方法)に従って自分のメールアドレスで登録・メール確認を行います。Firebase管理画面へのログインと、アプリ利用者の登録・ログインは別です。確認済み本人だけが自分の記録を読み書きできること、確認用記録の登録・再読み込み・訂正・削除が反映されることを確かめてください。

設定が不足するとアプリに案内画面を表示します。設定値不足は `.env` と再起動、`auth/operation-not-allowed` は認証方法、`permission-denied` はメール確認とルール適用先を確認してください。秘密鍵・Googleログイン情報・アプリのパスワードを共有しないでください。

Firebase CLIが `Cannot find module` で起動できない場合は、npmキャッシュの欠損が考えられます。上記の `npx -y firebase-tools@latest` を `npx --cache .runtime/npm-cache -y firebase-tools@latest` に置き換えて取得できます。`.runtime/` はGit管理対象外です。

### Emulatorだけで試す

実際のFirebaseプロジェクトへ接続せずに試す場合は、Java 21を用意し、`.env` の `VITE_USE_EMULATORS=true` を設定します。開発モードでは固定のデモ設定を使うため、4つの `VITE_FIREBASE_*` は空欄のままで構いません。

1つ目のターミナルで起動します。

```sh
npm run emulators
```

2つ目のターミナルで起動します。

```sh
npm run dev
```

`http://127.0.0.1:5173` を開き、テスト用のアカウントを登録します。確認メールは実送信されず、Auth Emulatorのターミナル出力に確認用リンクが出るため、そのリンクで確認してアプリの「メール確認の完了を確認」を押します。実在する認証情報や個人の記録は使わないでください。

スクリプトは `demo-qualification-records` を使用し、Authは `127.0.0.1:9099`、Firestoreは `127.0.0.1:8080` へ接続します。Emulator UIは無効です。データの永続化用export/importは起動スクリプトに含まれないため、終了後もデータが残る前提では利用しないでください。クラウドに戻すときは `VITE_USE_EMULATORS=false` にして開発サーバーを再起動します。公開用の設定でEmulatorを有効にしないでください。

### 検証・ビルド

| コマンド               | 内容                                                      |
| ---------------------- | --------------------------------------------------------- |
| `npm run lint`         | ESLint                                                    |
| `npm run format:check` | ソース・テスト・設定のPrettier確認（READMEは対象外）      |
| `npm run typecheck`    | 本番モードの型チェック                                    |
| `npm test`             | ドメイン処理・JSON検証などの単体テスト                    |
| `npm run test:rules`   | Firestore EmulatorでSecurity Rulesを検証（Java 21が必要） |
| `npm run test:e2e`     | Chromiumで主要操作を検証                                  |
| `npm run check`        | 型チェック・単体テスト・本番ビルド                        |
| `npm run build`        | Hosting向け成果物を `dist/` に生成                        |

E2Eの初回実行前は `npx playwright install chromium` でブラウザーを用意します。LinuxでOS依存ライブラリも必要な場合は、CIと同じ `npx playwright install --with-deps chromium` を使用します。E2EはAuth・Firestore Emulatorと開発サーバーを自動起動し、既存サーバーを再利用しません。標準の5173・8080・9099ポートを使用中のプロセスと競合させないでください。開発サーバーのポートは `E2E_PORT` で変更できます。

### Hostingの公開とCI

[Validate](.github/workflows/validate.yml) はpush・pull request・手動実行で、`npm run check`、Rulesテスト、ChromiumのE2Eを実行します。

[Hosting用ワークフロー](.github/workflows/hosting.yml) はmainへのpushまたは手動実行で起動し、GitHub変数 `FIREBASE_PROJECT_ID` が設定されている場合に実行します。型チェック・単体テスト・Rulesテスト・ビルドの後、Firebase Hostingのliveチャネルへ公開します。利用する場合は、対象プロジェクトを確認したうえで次をGitHubに設定してください。

- Variables：`FIREBASE_PROJECT_ID`、`VITE_FIREBASE_API_KEY`、`VITE_FIREBASE_AUTH_DOMAIN`、`VITE_FIREBASE_APP_ID`
- Secret：`FIREBASE_SERVICE_ACCOUNT`（対象プロジェクトのサービスアカウント情報。READMEや `.env` に貼り付けません）

`FIREBASE_PROJECT_ID` が空なら公開ジョブはスキップします。設定が不完全なら公開に失敗するため、変数だけ設定して公開準備が完了したとは扱わないでください。公開時は `production` 環境を使用します。Firestore Rules・インデックスの適用はHosting公開とは別に管理します。
